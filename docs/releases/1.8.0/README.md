日期：2026-11-03。当前版本：1.8.0。范围：本地源码维护更新；未推送、打标签或发布远端版本。

## 结论与版本边界

本次采用最新工作区为基准，保留近期通用元件、工程引用和分析记录实现，修复一、二审中仍适用且适合维护版本的问题。此前源码的 2.0.0 标识统一调整为 1.8.0；功能没有退回旧版本。历史 `docs/releases/2.0.0`、一审、二审及真实案例验收证据继续保留。第三轮全面审核和 2.0 大优化尚未开展。

**1.8 是维护版本，不是“旧审计全部通过”的声明。** 下表明确区分本次修复、近期代码已改变的问题以及仍待验证/整改的问题。尤其不能把几何稳定性当成功率最优、实际起振或实验已经确认。

## 产品判断：通用工作流优先

产品目标是通用的 Agentic 激光光学仿真软件。用户是围绕实验任务工作的激光实验人员，日常需要把不完整目标、已有器件、规格书、测量与装调限制整理为可追溯工程，选择适用模型，比较不同条件，补充证据，保存版本并复算。

通用工作流为：识别目标及物理问题 → 整理事实、来源与未知量 → 建立/修改工程对象 → 选择有明确适用范围的工具 → 计算及比较 → 解释结果和缺口 → 补测、采用与复算。模型只覆盖其中一部分时，应明确界限；不得补造器件参数或以特定案例提示词掩盖缺失能力。

普通换件、改参数、改布局、换目标和补数据应改变工程数据与工具调用。新物理能力应扩展独立模型及契约。本次通过驻波腔和单程传播前端流程，以及不同功率单位、负曲率、库存权限与既有通用替换回归检查这一原则。没有新增按某个晶体或腔型定制的业务页面。

## 2.0 第三轮的唯一推荐路线

沿“通用实验工程 + 明确物理工具契约 + 证据及采用状态”深化现有架构。先处理证据真实性与授权边界，再统一测量来源/单位/不确定性、库存约束和历史引用，最后优化整体信息层级与性能。不要按每个真实实验复制模块或新增专用提示词。

第三轮应至少覆盖单程传播、不同腔型、多元件替换、无光学腔的测量分析、不完整资料和外部服务故障。每类从前端发起、修改、运行、追溯和恢复，并独立验证物理计算。增益/功率/热场等新模型需声明假设、输入要求及适用域，再决定是否能支持“最优”结论。

本次没有重跑真实模型、PostgreSQL、全附件格式、所有异常分支、全站无障碍、打印导出或真实实验。它们是下一轮明确的验收范围，不记作已通过。

## 本地使用与兼容

使用项目原有启动方式重启前后端即可载入 1.8.0；前后端版本检查需一致。保留现有数据库与上传文件，按原有机制运行用户近期新增的数据库迁移。本次维护本身没有新增数据库迁移，也没有在真实数据库执行迁移。

新运行的功率拟合统一存 W，保留输入单位元数据；历史记录不就地改写。镀膜文件需要明确单位才能重新计算。新验证会拒绝以前可能静默接受的损坏数据，错误中给出行号或对应字段。预览环境中的合成项目不属于真实实验数据。
