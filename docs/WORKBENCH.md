# BeamWeft optical workbench

Open an experiment to work on its optical layout, compare calculations with observations, or ask the Agent to work on the same project. The manual workbench and the Agent share the project's Python/NumPy ABCD engine and its SciPy scalar Fresnel propagator. BeamWeft uses Rezonator as a reference for cavity calculations.

## User workflow

Opening a project brings its name and canvas into view. From the project title, press Tab and activate **跳至光路图** to go straight to the current drawing. This also works with a port network or an empty design. On a desktop you can collapse the inspector to use the full drawing width. Selecting an optic or port to inspect brings its properties back. On a phone the inspector opens over the lower part of the drawing. Escape returns keyboard focus to the control that opened it. Each Agent task records the model it received. The canvas shows that starting version while the task runs. You can continue editing, previewing and saving the same optical project, or keep a separate variant. If the main version advances while you have local edits, the canvas retains your draft and shows the differences. Review the changes to combine them, or use **方案与版本 → 从当前光路另存方案** to keep your local model with its original source and base. [Concurrent editing in two workbench windows](../output/acceptance/agent-concurrent-edit/README.md)

For inventory-backed optics, you can compare candidate substitutions and their calculated detector spots during an Agent task. Physical replacement becomes available when the task ends. The commit checks the reviewed preview against the catalog item and the selected project revision. [Inventory comparison during a live task](../output/acceptance/agent-concurrent-edit/inventory.json)

A plane-parallel material segment on the main beam or an incident arm can use a stock window or a declared stack of media. Select the segment on the canvas and open **更换库存实物**. The picker and the Agent use the same preview. When thickness changes, the default preserves the surrounding air gaps. Fixing the entrance face absorbs the difference in the following air gap. Fixing the exit face uses the preceding gap. The preview gives both face coordinates along the selected path and the actual gap adjustment. An adjacent solid, locked spacer or insufficient travel prevents that mounting choice. A single-pass path has its own length and a swap on that path preserves the case’s separately recorded cavity length. Observe how a proposed installation affects the measuring instrument. A station registered in bench coordinates keeps its coordinate along the unfolded main path. A station registered by depth follows its reference segment. The workbench reports movements, changes of sampled medium and coordinates that become ambiguous at an interface. For example, after a 2 mm window was replaced by an 8 mm window on the same entrance face, a camera registered at 34 mm stayed there. An inventory entry opened from the library starts as unclassified. Opening the same editor from a particular mount supplies that mount's category. A positioned train with an incomplete source remains editable. ### Comparing a pump distribution with a signal mode

At an observation plane, **比较截面光场** evaluates two registered Gaussian beams. Intensity similarity compares the shapes, sizes and centroids in that plane. At equal wavelength, the coherent spatial projection also accounts for wavefront curvature and relative pointing under the displayed polarization assumption. Use **保存** in this comparison to retain the plane, beam identities, results and geometry for replay or a comparison of candidate designs.

For a crystal or another uniformly absorbing segment, select **沿增益段计算泵浦与信号重叠**. Supply the absorption at the pump wavelength and select the signal path. The calculation supports a Gaussian pump described by the project or a discrete incoherent pump described by positions, directions and optical-power weights. For the latter, select its launch path and use a registered ray bundle from a file-based calibration or a source study. The bundle's transverse positions and reduced slopes include its offsets and pointing in the launch frame. The solver transports each weighted ray through the actual ordered matrices and entrance apertures to each shared segment.

Within a segment the signal intensity integrates to one over each transverse plane. The ray calculation evaluates that intensity along each surviving pump trajectory, averages using the surviving optical weights, then averages along the physical length using normalized Beer absorption. The reciprocal has units of mm². A smaller effective area gives more spatial interaction per absorbed watt in the stated model. Comparing expected gain or threshold also uses the absorbed power, material parameters and cavity loss. This follows the spatial overlap of a normalized excitation distribution with the signal mode in an unsaturated gain model. [Experimental study and spatial gain model](https://doi.org/10.1364/OE.18.013993)

Keep the position and direction from each source row paired. An entrance photograph, NA or M² alone leaves that joint distribution undetermined. A source generated under a fill assumption carries its basis into the result. Numerical integration error describes the axial calculation. When two independent sample sets are supplied, their difference separately describes sensitivity to the ray sample. An unsupported signal profile or missing absorption data leave the affected segment pending while other segments can still yield a result.

### Revising a design decision

An experimental specification can call for a particular reading, such as a beam width at a receiver. Choose **最接近目标值** and enter the desired value in the unit shown for that output. BeamWeft retains the actual reading and its absolute distance from the target. The lower and upper acceptance limits always apply to the actual reading. A target can lie beyond a hard limit when the aim is to get as close as the permitted range allows.

In a saved comparison, `rows[].values` holds the readings and `rows[].target_deviations` holds the absolute differences for target objectives. A difference is a JSON number when a binary64 client can round-trip its decimal value, or a decimal string when that conversion would discard digits. This convention preserves ties and order for targets far outside the sampled range.

Each objective has its own physical scale. A candidate can improve the width while sacrificing collected power, so both candidates may be worth building. The comparison preserves these trade-offs and exposes each actual reading and deviation in the two-candidate view. Target distance uses a linear scale. For circular quantities such as optical phase across a wrap, the solver must first publish an appropriate phase-error observable. OpticStudio also distinguishes a desired operand value from its calculated reading, and documents how it combines residuals with weights. [Ansys OpticStudio merit function](https://ansyshelp.ansys.com/public/views/secured/zemax/v26103/en/opticstudio_user_guide/OpticStudio_Help/topics/Modifying_the_merit_function.html)

A parameter search stores its sample coordinates, candidate calculation IDs, solver evidence, numeric results and decision criteria. A subsequent evaluation can reuse the same candidates with new limits, different directions of preference, or a new scalar published by the original calculation. The comparison table shows the old and new verdicts. A two-candidate view reports each value and the difference in its original units. With several objectives the first Pareto layer contains the feasible candidates for which improving one objective would require worsening another, within the sampled set. A limits-only assessment reports feasibility. [Multi-criteria decision making in pymoo](https://pymoo.org/getting_started/part_3.html)

The manual editor and the Agent action `reassess_study_search` call the same assessment. The result records the parent comparison and the original search. Historical values retain their original physical conditions, and table lookups require an unambiguous archived row identity. A missing value stays visible alongside the other results. The receiver of a project file can revise the criteria using the archived records even when the original solver plug-in is unavailable. Changing physical inputs or adding new sample coordinates requires another calculation.

To edit a candidate, open its calculation from the comparison and select **在画布打开独立方案** for the required layout input. A calculation bound to one arm or observation plane can reopen its complete source project, including the other arms, installed parts and parameter locks. A calculation supplied with a standalone optical layout can create a variant from the geometry it actually received. Launch distributions, detector acceptance and other study inputs remain available on the calculation record. The canvas header links back to the original calculation. To check a revised design, save the variant, return to the original calculation, bind the new geometry and confirm the reference plane and axes. The other archived inputs stay available for the rerun. The Agent can select the same layout input through `begin_optical_study`.

### Inspecting alignment margins

Open the adjustment view of a saved comparison with at least one hard output limit. The selected candidate supplies the nominal setting. One mode fixes other parameter groups at their recorded values. The other tests every recorded combination of those groups for each setting on the selected axis. A failure under any of those conditions excludes the setting. Missing required evidence leaves a setting undecided unless a violation is already established. Each result retains a link to the calculation that supports it. Coupled variables keep their full recorded tuple. The chart represents discrete evaluations, including separated passing regions and unknown positions. These counts carry no probability weighting.

The Agent can read the same evidence with `inspect_study_tolerance`. When a single adjustable coordinate has adjacent passing and failing samples with fixed conditions, `refine_study_tolerance` can evaluate midpoint settings using the original solver implementation until their spacing reaches a requested resolution. The saved comparison retains the source, original endpoint calculations, sampled values and the stopping reason. Completion of a midpoint check may reuse a saved calculation. The execution receipt counts newly computed results, reused results and attempts without a calculation record. An unknown midpoint stops the search. Neither a sparse grid nor local bisection establishes acceptance everywhere between points. For comparison, OpticStudio describes iterative inverse sensitivity and explicitly considers the treatment of compensators. BeamWeft holds the other coordinates fixed during a refinement. [Ansys inverse sensitivity method](https://ansyshelp.ansys.com/public/Views/Secured/Zemax/v251/en/OpticStudio_User_Guide/OpticStudio_Help/topics/Inverse_Sensitivity_Analysis.html)

### Choosing settings before or after a measurement

In **分析记录**, open the baseline calculation, select a saved search under **参数搜索与方案比较**, and expand **比较固定与按工况调节**. For each group of inputs, identify what the experimenter chooses at design time, what they can distinguish before adjustment, what remains hidden, and which controls they can actually set. Linked coordinates such as two mounts on one carriage move together. Changing a role lets the experimenter ask how much a measurement would help. The Agent uses the same operation, `inspect_adjustment_policy`.

A fixed setting qualifies when it meets the recorded hard limits in every sampled condition for that design. A measurement-dependent setting qualifies when each distinguishable condition admits at least one setting that works across all its hidden variations. The view retains every qualifying alternative and the candidate calculations that support each decision. An established violation rules out that setting. A missing measurement or calculation can leave it undecided. Archived readings with no historical solver fingerprint retain that limitation. The user supplies the assumptions about measurement resolution and attainable controls. Conclusions cover the discrete grid. Yield estimation requires a probability model, and performance between samples needs independent evidence. OpticStudio similarly lets a designer specify physical compensators. The separation of decisions made before and after information arrives is also the basis of adjustable robust optimization. [Ansys compensator definitions](https://ansyshelp.ansys.com/public/Views/Secured/Zemax/v251/en/OpticStudio_User_Guide/OpticStudio_Help/topics/Defining_Compensators.html) · [Ben-Tal et al., Mathematical Programming](https://www2.isye.gatech.edu/~nemirovs/MP_Elana_2004.pdf)

Each Agent inspection carries its own tool record and a workbench link with the chosen roles. A single saved comparison can therefore support several independently reopenable interpretations. For a sequence of adjustments on the same physical stage, also check the travel required between settings and the time available to move it. The sampled comparison tests each operating condition independently.

On a single-pass project, open **主光束参数** to enter the radius, wavefront and M² at the source plane. The two transverse axes initially share these values. Choose **尚未确定** for an unmeasured wavefront. A measured radius is still available at the source plane, and the other axis can still propagate if its inputs are complete. For older scalar projects, a blank R retains its original waist assumption. Choose **按 T/S 轴编辑光源** to review these assumptions or mark a condition unknown. Widths from a second-moment fit can be used in a propagation study. Coherent diffraction also requires an appropriate field model and known alignment.

Open a case to see the main path and each incident path on the same unfolded longitudinal scale. Each incident row identifies its wavelength and entry segment. ### Inspecting the transverse field on the canvas

In a saved project, open an observation plane and select the beam name in its results table. **查看引用状态** shows the radius, width convention, wavefront, M², center and pointing at that station. When the saved project provides comparable predictions, the report overlays its beam profile and compares two specific changes. One scales the transverse widths. ### Working with the Agent

Name the project and open **Agent 对话** on the canvas. You can start with a goal, parts list, constraint, measurement or unresolved observation. Attach images, documents or instrument data. The Agent can inspect the project, earlier conversation, saved tool outputs, artifacts and inventory. Selecting an object on the canvas preserves its path or port identity when the Agent reads the revision used for the question.

The Agent decides which available tool to call and inspects its return value before choosing the next action. This supports combined tasks: retrieve a previous layout, independently recalculate it, scan a spacing, compare the result and ask for a measurement that resolves the remaining uncertainty. Users do not have to select the appropriate physics module themselves.

Results distinguish four outcomes:

- `completed`: the requested deliverable has been produced within its stated model scope.
- `partial`: useful results exist and work remains.
- `needs_input`: a user answer is necessary. Each question includes its purpose, a way to obtain the information and the expected units/format.
- `unsupported`: the required capability is absent, with a concrete alternative or next step.

A reply starts another run in the same conversation, including previous questions and saved results. Tool inputs, outputs, errors, timing and final artifacts persist. Model/network failure preserves successful tool outputs and creates a partial result. Stop prevents later model responses from triggering new calls; an already executing request can take until its timeout to settle. The local runner is not a distributed job queue.

If a model labels a result `completed` while also asking required questions, the service conservatively normalizes it to `partial` (when successful tool results exist) or `needs_input`. This preserves the useful answer without spending another model call to repair only its status. Evidence references still require successful, recorded tool calls.

Continuous beam envelopes sample the neighborhood of a waist inside uniform media and thick lenses. In an ideal quadratic-index medium, the squared paraxial radius is sinusoidal in twice the gradient phase. The workbench solves its maxima and minima separately for each beam and axis. If resolving all oscillations would exceed 1,024 points for one element and axis, the drawing keeps both end faces, opens a gap over that element and reports its analytical radius range, first minimum and spatial period. ## Implementation

An installed study can declare a typed `OriginalFile` in its Pydantic inputs. For example, a study can take `signal: OriginalFile` and an optional `dark: OriginalFile | None = None`. Each value identifies a case attachment and may pin its expected SHA-256. During execution the host verifies ownership and content, pins the digest in the saved inputs, and provides a seekable binary stream as `signal.stream`. Nested models and sequences of originals are supported and each reference has an independent cursor. The host closes the streams when execution ends. Trusted packages supply the decoder. Opening the saved result only needs the stored definition and output. Top-level file inputs appear as archive pickers in the manual form, and the same input schema is available to the Agent.

A reader can subclass `OriginalFile` and implement the class method `recognizes(cls, prefix: bytes, *, complete: bool) -> bool | None`. The directory passes up to 64 KiB from the archived bytes. Return `True` for a recognized container, `False` when the content rules the reader out, and `None` when more information is needed. The optional hook also applies inside structured inputs. Search with `attachment_id` to receive candidate argument names and their recognition status. A reader without the hook remains available for trial. Execution always uses its full decoder and physical checks. An ordered list of originals has a file picker with move and remove controls, and its saved inputs preserve the order and individual hashes.

For two-dimensional results, `RasterView` describes the axes, intensity array and coordinate directions. Optional chart series overlay the raster. A method can declare `pixel_window_input` when its axes address original pixel indices. After a user zooms, integer centers inside that viewport define the new acquisition window, clipped to the plotted source extent. The workbench keeps the previous record and evaluates the new window from the archived bytes with the same input recipe.

A registered study supplies its input schema, physical ports and result presentation. The manual run, the Agent tool receipt and the case archive use the saved study definition. A table column can address a nested series, for example `channels.*.voltage_v`. Columns drawn from the same child collection appear together, with the parent acquisition repeated on each row. Empty collections preserve the parent and its diagnostic. Columns reading different collections remain separate arrays because their row correspondence is unknown. Flat tables and scalar metrics use the same contract.

Each port can declare named operating conditions and where to read their values. A consumer can require matching conditions, carry source conditions into its output and compare the origins of two inputs. Original file columns retain the source hash, selected rows, units and the evidence for declared acquisition conditions. Engineering identities such as a particular pump path and sample should come from the frozen project. A documented transfer between two known sources is visible in the saved result. The author of a physical model still decides which conditions matter for its predictions.

### Single-pass power on a saved optical path

A primary single-pass system can have a `single_pass_power` budget. A pump or probe entering a resonator can have its own `incident_paths[].power_budget`. In the workbench, select an element on the diagram to see the entering and leaving power for that beam. Expand its power budget below the diagram to enter the source, choose a loss law for each element, or inspect the calculation at an observation plane. Entry, exit and depth use the same geometry as the beam-radius calculation. A project may have enough data for a power budget while its incident radius is still unknown.

Each budget is tied to one wavelength. A whole-element retained fraction can describe transmission, a selected reflected beam or a measured throughput. Alternatively, specify both interface factors and either a homogeneous **intensity** absorption coefficient (internally per mm, natural exponential) or an internal transmission at a reference thickness. Under the single-pass model, a shared physical interface contributes one factor across both segments. For internal transmission data, record whether volume scattering can be neglected before attributing the internal loss to absorption. Unattributed loss may contain reflection, scattering, or absorption of unknown origin. The calculated absorbed power alone does not determine heat deposition, inversion or laser output. The model assumes passive linear response, axial path length and no multiple reflections.

Use the optional `downstream` list to follow a pump through immediately consecutive homogeneous host segments. Each segment accepts its refractive index at the pump wavelength. A break in the route limits the calculation to the connected prefix. Missing passive factors give bounds, and a missing source wattage leaves normalized fractions. The ranges are envelopes under independent input bounds. Their endpoints may come from different parameter combinations. Entering an experimentally established value or a datasheet value requires a source reference. Earlier revisions keep the assumptions and results used at the time.

The Agent can recalculate an exact saved model with `analyze_path_power({"revision_id": 42})`, analyze the latest with `{}`, or evaluate an unsaved proposal via `layout`. The saved model and the live preview call the same calculation. Case ownership and access checks apply to saved revisions. The results record the source inputs, per-stage accounting, selected observation planes and unbound stage IDs.

### Compare an instrument run with the model

Archive an original in the case, save the intended project revision and open **与功率计原件对照** in the workbench. Choose the beam and the actual measurement boundary. The near and far faces of a thin component may have the same axial coordinate and different optical powers. A reference-plane representation with no beam radius or positive propagation length can be used when only a lumped transmission measurement is known.

Select the row range, channel columns and units from a delimited text file or Excel worksheet. A photograph, document or other case original can supply a single transcribed reading with a page, region or record identifier. A synchronous reference may be taken at the source or at any preceding address on the same path. The solver evaluates the subpath between the two chosen locations, accounting for the volume and interfaces crossed. This cancels common upstream losses even when their values are unknown.

The result preserves the raw numbers, channel units, row numbers, archive hash, calibration inputs and model revision. The software converts dBm to watts before subtracting a declared dark offset or applying a tap multiplier. Instrument error bounds apply to the corrected full-beam watts. A missing bound stays unknown. A zero reference prevents division on that row. A wavelength or acquisition mismatch retains the original observations and suppresses differences. The arithmetic mean of the per-row ratios weights each sampling row equally. Readings used to set model parameters can be marked as such.

The chart shows each row in acquisition order. Fixed-source predictions and predictions using that row's reference are drawn separately. The instrument bounds come from the user. The plotted sequence alone supplies no confidence level or evidence that a particular optic absorbed the missing power.

`read_power_measurements` lists locations and records for a revision. `compare_measured_power` uses the same comparison as the manual workbench. Agent context may sample long lists. To inspect original contiguous rows, use `read_tool_result` with the tool call ID, the list path (for example `points`), a zero-based `offset` and an optional `limit` of up to 24.

### Extending the workbench

A self-contained study with an ordered layout input port can declare that input in `Study.live_layout`. The canvas discovers its form, preview and result views from the registered definition. Manual runs and Agent runs share the versioned method. A device provider can declare `ElementLaw.scalar_transfer="quadratic_phase"` to contribute a lossless thin scalar phase screen with aligned T/S axes. Each axis supplies a reduced ray matrix of the form `[1, 0, C, 1]`. The host validates this promise before using the phase screen.

Live studies receive the complete layout by default, including network components’ schematic positions. Set `Study.ignores_diagram_positions=True` if the method produces the same results with `diagram_xy` omitted from every component. The canvas can then keep the current result during a schematic rearrangement. Physical link lengths, phases, field offsets and optical prescriptions still travel with the preview.

Model a change of apparatus in the case project first. For example, a physical component can own one or more consecutive elements on a particular path. The same optical prescription can describe two lenses on separate mounts or one rigid lens barrel. The canvas and observation plot read the same resolved layout. Dragging a mounted member moves the whole object, and changing its position in the incident-path list preserves member order.

For a new equation or file-analysis method, define the inputs, physical assumptions, outputs and solver version in a `Study`. The manual workbench and the Agent discover the same installed method. A device with a supported optical representation can also publish its law through that interface. Case files carry the settings and evidence used for a particular experiment. The base Agent actions in `backend/app/workbench/tools.py` handle operations such as reading or saving projects and invoking calculations. New case layouts, equipment selections and measurement values use the existing operations.

- `backend/app/workbench/service.py`: model → validated call → persisted real result → model loop. A maximum of 16 model turns / 32 executed tool calls bounds each run. Only `finish` ends a successful model turn; invalid output is returned for repair.
- `backend/app/workbench/contracts.py`: typed result/questions/evidence contracts. `needs_input` without an acquisition guide, or a fabricated tool evidence id, fails validation.
- `backend/app/workbench/optics.py`: typed application adapter around the dependency-free physics library. Distances are physical mm; wavelengths vacuum nm; radius is 1/e² intensity; propagation uses reduced q with explicit medium conversion.
- `backend/app/providers/tool_calling.py`: native OpenAI Responses, Anthropic Messages and configured Chat Completions-compatible provider adapters. Responses continuation preserves encrypted reasoning items and call ids with `store=false`.
- `backend/app/api/workbench.py`: case-scoped submit/read/stop APIs. Existing ACL rules are reused, not redesigned.
- `frontend/src/components/ExperimentWorkbench.jsx`: task input, conversation, results, actionable questions, tool traces and prior design artifacts.

No database migration: existing chat, task, step, tool-call and generated-content tables are reused. Old fixed module APIs and chat are retained as **旧版模块助手 / 旧版对话记录** for compatibility; new tasks use the workbench.

The **光学工程** tab is usable without a model request: expand element parameters, edit free geometry, save a new version and calculate a 2D map. Owned hardware requires an explicit unlock to change. Historical selection is read-only until saved as a new version; the revision's own scan is restored on reload. Element-table wavefront radii use the air-equivalent reference convention, while segment profiles use their physical medium.

`scripts/recalculate_design.py --case-id <id> --evidence <json> --output <json> [--write]` is an explicit operator fallback for an already supported linear design when a model service is unavailable. Quoted fact updates are validated against supplied source text. Default execution writes only a local numerical report; `--write` appends a clearly labeled direct-kernel run, design, optical project and stability map. It never claims that a real model completed that run. Preserve a database backup before using this operational command.

## Validation

The canvas conversation uses the same message, attachment selection and submission logic as the project conversation. An object reference identifies what the researcher selected. A draft snapshot identifies which model was visible at submission. Opening or closing a conversation, browsing versions, and inspecting the parts library are view changes. On touch screens, a tap opens the component inspector, and moving a component takes a deliberate drag. Precise position entry is also available. These alternatives follow the interaction principle discussed in [W3C's guidance on dragging movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html).

### Rechecking archived calculations

The optical model and the calculation that used it have separate identities. A saved analysis stores its solver receipt beside the numerical output. The receipt records the method, provider, declared version, application source fingerprint, selected Python and scientific-library versions, platform, and implementation fingerprints for referenced registered optical device models. The application fingerprint covers the server's packaged Python and JSON source at process start, so unrelated source edits can also change it. The recorded environment is not an inventory of every transitive binary or machine setting.

The read-only project recheck loads the selected revision or study snapshot, runs the installed solver using its frozen prescription, and compares JSON outputs by path. Array order matters. Shared numerical values are compared exactly; a missing subtree or changed array length counts as one structural difference. Counts cover the full comparison and the response includes up to 16 differing fields. The echoed system definition, display engine name and solver receipt are handled separately. A matching result supports reproducibility for those inputs. Accuracy against physical measurements is a separate validation. The UI and the Agent capability `recheck_optical_project` use the same calculation.

If the current reader supplies defaults or converts fields, the recheck reports a separate input comparison. The archive stays immutable. This lets a researcher inspect a historically absent refractive index even when the calculated beam happens to be identical.

Registered study records retain their capture-time receipt. The currently installed method can be inspected separately. When the archive lacks a usable receipt, the installed description has method-only scope and cannot establish the original device dependencies. Reusing a saved result is marked explicitly. Native-grid export verifies the reconstructed grid against its archived grid digest and includes both the saved and verification-time solver records when available.

Registered methods should express external calibration data as inputs or versioned original-file evidence. The receipt covers the declared implementation and environment. Mutable callable state that cannot be fingerprinted disables result reuse. The distinction between an input entity, the calculation that used it, and its resulting artifact follows the provenance concepts in the [W3C PROV Primer](https://www.w3.org/TR/prov-primer/).
