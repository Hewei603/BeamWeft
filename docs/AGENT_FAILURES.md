# Agent 任务中断后，实验者应该得到什么

一个实验者回到工程前，首先要做的是决定下一步。即使模型服务已经断开，工作台仍要根据已保存的工程与工具记录，用自然语言交代这次工作。系统生成的交接说明与模型自己的最终答复分别标识。运行状态和科学结论也分别记录。一次任务可以因服务中断而失败，同时留下能继续使用的计算。

## 一份交接应回答的四个问题

1. **停在哪一步，为什么？** 先写实验者能理解的原因。供应商明确拒绝认证时，说明需要核对哪一组服务与凭据。只有连接中断事件时，说明本轮没有收到完整答复，责任端仍待排查。错误码、退出状态等技术依据留作复核。
2. **哪些工作已经做成？** 只从本轮已持久化的工具返回中提取内容。保存了工程修订、读到文件、算出数值和查到可用工具是四种不同进展。一个科学读数要能回到对应的条件、单位和计算记录。原件尚未读取时，应清楚说明目前没有读数。
3. **哪些问题还没有答案？** 保留工具明确提出的缺项、超出适用范围和失败记录。没有证据的工作保留为待确认。仅凭用户目标或一句操作意图，不能断定某项计算已被执行，也不能声称已经量过设备。
4. **现在可以做什么？** 说清谁要做哪件事、在什么入口操作，以及做完后如何判断可以继续。出现配置或付款问题时，先解决相应前提。工程允许继续时，用户可载入原目标和可引用的记录，核对草稿，再发起下一轮。原运行与后续运行各自保留。

## 不同原因对应不同恢复动作

| 已掌握的依据 | 应给实验者的指引 |
| --- | --- |
| API 返回 401 或 403 | 对 401 核对服务商、对应凭据和已配置的接口地址。对 403 核对模型或项目访问权限，选用当前账户已获授权的模型。 |
| 402，或带明确额度耗尽原因的 429 | 核对该账户的计费与额度，恢复后再提交。短时间反复提交不能补足余额。 |
| 供应商明确限速，或仅返回含义未细分的 429 | 有限速依据时按供应商窗口等待；原因未区分时同时给出限速与额度的排查路径。 |
| CLI 或网络连接中断、超时 | 提示用户在相应配置中验证连接和登录。对超时说明等待上限和本轮是否取得输出。连接验证成功后可以继续原目标。 |
| 物理工具缺少输入或超出适用范围 | 指向该工具的诊断与输入，说明仍可使用的部分。用户可以补充测量，或明确创建另一种假设并分别比较。新的假设有自己的物理含义。 |
| 用户停止、执行归属待确认 | 保留停止或待确认状态。先核对原任务是否仍在运行，再决定是否补做，防止重复写入工程。 |

## 继续时使用的工程版本

继续任务时，界面会指出草稿将使用哪个工程版本。若中断前已保存新结果，用户可以沿用该版本，也可以回到原输入。历史记录没有留下起点时，界面请用户明确选择。这样，即使同事在中断后又修改过工程，接手者也能从自己核对过的起点发送。[三个原生工程的实际续跑请求](../output/acceptance/agent-failure-handoff/resume-basis.json)

## 验收方式

用独立工程分别触发有成果和无成果的中断，从工作台检查提示，打开引用的记录，按指引恢复，再核对前后两轮。在合成光谱工程中，服务鉴权中断前已算出 2.340 mW。恢复后的任务读取了这条计算记录，原始回执仍可打开。服务故障由本地测试端点注入，求解、归档和界面操作均经过实际应用。[工作台故障与恢复实测](../output/acceptance/agent-failure-handoff/README.md) · [公网与受控接口分别验收](../output/acceptance/ai-interface-final/README.md)
